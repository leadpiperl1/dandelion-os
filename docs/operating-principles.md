# Dandelion Operating Principles

The Dandelion project is built on a simple doctrine:

- Occam: prefer the simplest working design
- Landauer: respect the cost of computation and information
- Grand Nagus: govern intelligence with stewardship, not chaos

## 1. Simplicity is a feature
We value the smallest system that still performs its purpose correctly.

- Favor explicit invariants over hidden cleverness
- Prefer deterministic behavior over ad hoc tuning
- Reduce state when possible
- Keep safety and control explicit

If a feature cannot be described clearly, it is not yet ready.

## 2. Information has a cost
Landauer reminds us that computation and information processing consume energy and impose real costs.

We will:
- avoid unnecessary recomputation
- prefer bounded telemetry over noisy logging
- keep outputs explainable and intentional
- treat data movement and storage as engineering concerns, not afterthoughts

## 3. Human sovereignty remains central
The system exists to serve intent, not to replace judgment.

- Human oversight remains the final authority
- AI is a co-pilot, not an autonomous ruler
- Fail-closed behavior is preferred when uncertain
- Safety gates are explicit and auditable

## 4. Trust comes from verification
A system is only as strong as the evidence behind it.

We validate:
- build correctness
- deterministic checks
- strict compiler warnings
- artifact generation
- release integrity

## 5. The Dandelion standard
We build:
- bounded intelligence
- sovereign control
- verifiable trust
- disciplined simplicity

The goal is not maximal complexity.
The goal is maximum clarity under control.

“Least state, least waste, highest clarity.”
